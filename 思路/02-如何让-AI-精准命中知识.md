# 02 · 如何让 AI 精准命中知识

> 上一篇解决了"知识以什么形态存在"。这一篇解决"写某一章时，怎么找到该用的那条"。

## 问题的形状

知识库建好了，里面躺着几百上千条知识页。现在要写"隧道工程 > 超前地质预报"这一节，
需要从里面挑出真正该引用的几条。

朴素做法有两种，都不行：

- **全给**：把 1000 条知识页的标题全塞给模型，让它挑。上下文浪费巨大，而且模型在长列表里的选择质量会下降。
- **靠模型自由发挥**：不给列表，让它自己说要什么。结果它要的东西库里根本没有，或者名字对不上。

需要的是一个**逐级收窄的漏斗**：便宜的、确定性的手段先在前面拦掉大部分，只在真正模糊的时候才动用 LLM。

---

## 三级漏斗

最终实现是三层（`backend/app/services/matching.py`）：

```
待写章节路径，如 ["隧道工程", "超前地质预报"]
        │
        ▼
┌───────────────────────────────────────────────┐
│ 第一级 · 专业标签过滤                          │
│ 节点路径里的专业词 ∩ 知识页 tags               │
│ （"隧道" 只保留 tags 含"隧道"的页）            │
└───────────────────────────────────────────────┘
        │  候选从 1000 条 → 几十条
        ▼
┌───────────────────────────────────────────────┐
│ 第二级 · 标题相似度（字符 bigram Dice）        │
│ 去编号前缀后比相似度                           │
│   Dice ≥ 0.80  → 直接命中                      │
│   0.35 ≤ Dice < 0.80 → 进入模糊带              │
│   Dice < 0.35 → 淘汰                           │
└───────────────────────────────────────────────┘
        │  命中一批 + 模糊带一批
        ▼
┌───────────────────────────────────────────────┐
│ 第三级 · LLM 终判（只在模糊带触发）            │
│ 把"章节路径 + 候选的标题与 usage"给模型        │
│ 由它判断哪几条真的该用，并给出理由             │
└───────────────────────────────────────────────┘
        │
        ▼
    最终引用的知识页（每章最多一次 LLM 调用）
```

关键点：**大部分章节在第二级就结束了，根本不需要调 LLM。** 只有标题相似度落在
0.35~0.80 这个"有点像又不太像"的区间时，才花钱请模型看一眼。

---

## 第一级：为什么用"专业标签"而不是全量比标题

知识库里的专业分布是极不均衡的——桥梁、隧道、路基、轨道、房建、四电……
如果一份施组是铁路项目，知识库里有大量房建内容，那么"桩基施工"这个标题
在房建和桥梁里都有，光靠标题相似度会互相污染。

所以第一步用**专业标签求交集**：从待写章节的路径里提取专业词（"隧道工程 > 超前地质预报" → 隧道），
只保留标签匹配的知识页。

这里有个细节：**只在"节点路径确实有专业语境时才过滤"**。像"施工组织安排"、"资源配置"
这类全专业通用的章节，路径里没有专业词，就不做过滤，否则会把该用的全过滤掉。

---

## 第二级：标题相似度的坑

### 坑一：编号前缀干扰

知识页标题是全路径存的，形如 `3 隧道工程 > 3.2 超前地质预报`。
待写章节可能叫 `第三章 隧道 > 超前地质预报`。编号写法完全不一样，
直接比字符串相似度会得出很低的分数。

所以比较前先 **归一化**：剥掉编号前缀（各种 `3.` `3.2` `第三章` `（一）` 形式），只比语义部分。

### 坑二：只比叶子节点会大面积漏召回

这是实测踩出来的。原本的实现是"只比较叶子节点标题"，结果发现：

> `5.2 小临工程` 下面的 15 张子知识页，叶子标题都是 `⑴布局`、`⑵实施方案` 这类，
> 跟待写章节标题相似度全是 0 —— 全部漏掉，反而被同章的 `5.1 大临工程` 抢走了引用。

**修正**：路径中**带编号的真实章节段**（`5.2`、`5.2.2` 这种）也参与计分，
取该页所有编号段的**最高** Dice 值。而那些非编号的纯描述词段（如 `⑴布局`）不参与，
避免大范围误命中。

这个修正让"父节标题决定归属、子节细目各自可被召回"成为可能。

### 坑三：为什么用 Dice 而不是编辑距离

用的是**字符 bigram 的 Dice 系数**。中文标题短，编辑距离对字序敏感，
"超前地质预报"和"地质超前预报"编辑距离不小，但意思完全一样；
bigram 集合对这类语序变化更宽容。

## 第三级：LLM 终判的输入很有讲究

模糊带的候选交给 LLM 判断，但**给什么信息**决定了判断质量。

一开始只给了标题，结果模型判断得很随意——毕竟光看标题，
"超前地质预报"和"超前支护"确实很难说哪个更该用。

后来把知识页的 **`usage`（使用方式/适用场景）** 加进判断输入，效果立刻不同：

```
候选 1：《XX施组》隧道工程 > 超前地质预报
       使用方式：适用于隧道超前地质预报类章节，尤其需要说明多种手段组合时

候选 2：《XX施组》隧道工程 > 超前支护
       使用方式：适用于洞口段、断层破碎带的超前支护措施章节
```

模型看到"使用方式"之后，判断准确率明显提升。**这就是为什么上一篇说
`usage` 字段是知识页 schema 里性价比最高的一项**——它把"什么时候该用我"
这个只有人类知道的信息，显式写进了数据里。

> 本质上：**不要让模型去猜知识的用途，把用途写下来让它读。**

同理，工法匹配（`match_methods`）也是同一套漏斗，只是第一级换成
"节点专业词 ∩ 工法 `applies_to`"，第二级用"工法名 vs 节点标题的 Dice + applies_to 命中路径加分"。

---

## 防"抄错 id"

一个容易被忽略但很致命的点：**模型会编造 ID**。

如果给模型的候选列表是：

```
id=317: 超前地质预报
id=892: 超前支护
```

模型很可能在输出里返回一个不存在的 `id=445`，或者把 317 记成 371。

解决方案很土但很有效：**给模型看的是稳定序号，不是真实 ID**。

```
候选 1: 超前地质预报
候选 2: 超前支护
```

模型只回答"候选 1、候选 3"，程序再把序号映射回真实 ID。序号是连续的、短的，
模型抄错的概率大幅下降，而且**即使抄错也能被程序立刻发现**（序号越界），不会静默写入错误引用。

这个模式在项目里用得很广：章节索引选章、工法选型都一样。

---

## 代价与边界

**第一级的代价**：专业标签是 LLM 在提炼知识页时打的，如果标错了，这一页就再也匹配不上了。
缓解办法是标签取自一个受控的专业词表，不是让模型自由发挥。

**第三级的代价**：每章最多一次额外 LLM 调用。做了并发，实际影响可接受。

**已知边界**：
- 索引/知识页概要里没写到的内容，永远找不到。所以概要要写得全一些。
- 同义但字面差异大的表述（如"地质预报" vs "超前探测"）仍然依赖 LLM 终判兜底。
