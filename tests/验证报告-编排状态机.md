## 三、关键结论与踩坑

1. **langgraph 1.x interrupt 机制**：`interrupt()` 不抛异常，而是在返回 state 的 `__interrupt__` 键里放中断值（`Interrupt(value=..., id=...)`）；恢复用 `Command(resume=approval)`，而非把 approval 当 state 输入。这是与 langgraph 0.x 的关键差异。

2. **体量问题（架构级结论）**：真实施组目录展平后有 79+ 个叶子节，全量生成思路+正文需 158+ 次 LLM 调用，一次性 invoke 会非常慢（十几分钟）。**正确做法**：编排流程不能一次 invoke 跑完，应配合 TaskRunner 异步任务 + 进度反馈，让用户在编辑界面看到"正在生成第 N 章思路…"进度卡片，而不是干等。

3. **LLM 健壮性**：连续快速调用会触发百炼限流/断连（`WinError 10054`、`502`），已给 llm.py 加**指数退避重试**（MAX_RETRIES=4），并统一 `trust_env=False` 直连绕过系统代理。

4. **并发控制**：思路/正文生成用线程池并发（并发度 3），避免串行过慢，同时控制并发度避免触发限流。

## 四、下一步

2. 前端工作台接入：目录树渲染目录、对话区返回进度卡片、正文流式写入 TipTap 编辑器；
